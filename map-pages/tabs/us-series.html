系列 A+ 首图画廊 · 交付说明

一、交付物

单个 HTML 文件，画布 1280×720（PPT 16:9）。12 张 A+ 素材以 base64 内嵌，双击即可运行，不需要联网、不需要外部图片目录。

二、可视化预览

  • 三列 × 四格 = 12 个系列；每列上下循环滚动，三列速度不同。
  • 方向：左列向上、中列向下、右列向上（周期 26s / 31s / 28s）。
  • 每张图左上角白色色块显示系列名，字色深蓝 #1A3A5C（CSS 变量 --deepblue）。
  • 滚动是纯 CSS 动画，页面加载即动、不依赖脚本：每列轨道内直接写好两组相同内容，位移 0 → −50% 实现无缝循环。

三、交互

  • 点击画面：停止滚动，并把三列自动吸附对齐，完整呈现 3 列 × 4 格共 12 张整图。
  • 再次点击：恢复滚动。
  • 右下角「说明 / 源码」按钮不触发暂停。
  • prefers-reduced-motion 开启时关闭滚动，直接呈现整图。

「取值逻辑 / 设计规范 / 代码解读」三个页签是本文档的结构化版本；「MD 文档」是同一份文档的 Markdown 原文；「完整源码」是运行时自取的整页源码，可直接复制或下载。

3.2 抓取步骤与判定口径

  1. 打开详情页 https://www.amazon.com/dp/<ASIN>，等待约 7 秒。
  2. A+ 容器有两个，必须按页面位置判定（最容易出错的一步）
    • #aplusBrandStory_feature_div → 页面上「From the brand」品牌故事块（约 670px 高），里面通常只有 1 张通用品牌横幅，所有 listing 长得一样。
    • #aplus_feature_div → 页面上「Product description」标题下方真正的 A+ 内容（约 4200px 高）。
    • 判定方法：用页面 H2 文案对齐 Y 坐标 —— From the brand 的 Y 对应前者，Product description 的 Y 对应后者。
    • 取值时优先 #aplus_feature_div，不存在再回退 #aplus。
  3. A+ 图片全部懒加载：<img class="a-lazy-loaded" src="…/grey-pixel.gif" data-src="真实地址">，必须读 data-src，否则只会拿到 1×1 灰色占位图。无需滚动即可读到。
  4. 「大图」判定用渲染宽度，不用原始裁剪尺寸：地址里的 __CR0,0,W,H 是原始裁剪尺寸，不等于显示尺寸 —— 例如 __CR0,0,1660,1820 的图可能实际只以 _SX166_（166px）渲染，属于网格小图。正确口径：优先取 _SX(\d+)_，其次 __AC_SR(\d+),(\d+)，≥ 900 才算大图。
  5. 「第 N 张大图」= 把 A+ 模块按 DOM 顺序排开（先剔除被其它模块包含的嵌套节点），过滤掉所有小图后取第 N 张。
  6. URL 归一化：地址常带测量前缀 https://m.media-amazon.com/images/W/<id>/images/S/…，用 /images/W/[^/]+/images/ → /images/ 还原规范地址；两者内容完全一致。
  7. 去噪：过滤 grey-pixel、chrome-extension:、data:image 三类来源，并按 URL 去重。
  8. 下载与压缩：m.media-amazon.com 可直连下载原图（带 UA + Referer: https://www.amazon.com/）；入页面前统一缩放到宽 900px、JPEG q=82，再转 base64 内嵌。
Ekho 的特例：B0CM3CNBGY 的两个容器内容不一样 —— 品牌故事块是通用的「EKHO」氛围图，Product description 下才是商品专属的「Style Speaks Volumes」吧椅场景横幅，因此改用后者。

5.1 无缝循环原理

每列轨道（.track）里直接写好两组完全相同的内容（.group × 2），轨道总高 = 2 × 一组高度（684 × 2 = 1368px）。位移从 0 走到 −50%（= −684px）时，第二组正好落到第一组的起始位置，因此循环点没有跳变。

.track{animation:cUp 26s linear infinite;}
@keyframes cUp{from{transform:translate3d(0,0,0);} to{transform:translate3d(0,-50%,0);}}

两组必须写在 HTML 里（而不是加载后用 JS 克隆）：否则脚本被禁用时只剩一组，−50% 循环会露出空白。向下滚动只需把关键帧反过来（from{-50%} to{0}）；三列速度不同，做法是共用同一组关键帧、只覆盖 animation-duration。

5.2 为什么滚动必须做成 CSS 动画（实测踩过的坑）

把滚动交给 JS 的 requestAnimationFrame 虽然更灵活，但有一个真实踩过的坑：看板把本页嵌在 display:none 的面板里（.panel 非激活即隐藏），此时页面内任何元素的几何量都是 0。旧写法在脚本执行时量「一组高度」，量到的是 0：

var GROUP = Math.round(firstGroup.getBoundingClientRect().height); // 隐藏时 = 0
var speed = GROUP / 26;                                            // 0 → 永远不动
// 而且不会重测：切回该面板后依然是 0，页面保持静止

改成 CSS 动画后，位移由样式表负责，不经过任何运行时测量，因此不受容器可见性影响——复制 HTML + CSS 即会滚动；脚本只负责「点击吸附」这一项增强，删掉也不影响主效果。

本页的吸附增强同样做了加固：一组高度改为由 CSS 令牌推导（--card-h + --card-gap 再乘张数），不依赖布局是否已经可见，因此在看板的隐藏面板里也能正确初始化。

5.3 点击吸附（JS 增强）

JS 启动时先把 CSS 动画关掉（track.style.animation='none'）接管位移，再维护一个位移量 pos：

  • 自由滚动：pos += dir × speed × dt，并始终保持在 [0, GROUP) 区间内。
  • 点击吸附：目标 = round(pos / STEP) × STEP，用 easeOutCubic 在 460ms 内过渡。
  • 由于 pos 恒在 [0, GROUP)，最近对齐位必然落在 [0, GROUP]，无需再做取模回绕，也就不会出现顶部或底部露空。
function beginSnap() {
  snapping = true;
  cols.forEach(function (c) {
    c.from = c.pos;
    c.to = Math.max(0, Math.min(GROUP, Math.round(c.pos / STEP) * STEP));
    c.t = 0;
  });
}

5.5 CSS 要点

  • .col{overflow:hidden} 形成滚动视窗，卡片在列边界被裁切。
  • translate3d 而不是 top：位移走合成层，不触发布局重算；will-change:transform 进一步提示 GPU。
  • 卡片用 margin-bottom 而不是父级 gap：这样「一组高度」= 4 × (160 + 11) = 684，与列高严格相等，−50% 的循环位移才精确。
  • 图片放在 CSS 变量里（--img-xxx），两组内容共用；若写成两个 <img> 的 base64，文件体积会翻倍。
